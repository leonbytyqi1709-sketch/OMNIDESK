Ich arbeite am Projekt OmniDesk – einer modularen All-in-One-
Produktivitaets-Webapp fuer IT-Profis (Spezifikation liegt als
omnidesk_spezifikation_v2.pdf im Projektroot, bitte zuerst lesen).
Das Repository: https://github.com/leonbytyqi1709-sketch/OMNIDESK.git

WICHTIG – lies zuerst diese drei Dateien im Projektroot:
  1. DOKUMENTATION.txt  (kompletter Entwicklungsstand, Architektur,
     bekannte Bugs/Loesungen, offene Punkte)
  2. OFFENE_ARBEITEN.txt  (DETAILLIERTE Uebergabe der unterbrochenen
     Arbeiten: exakter Datei-Stand, fertige API-Endpunkte, praezise
     naechste Schritte pro Aufgabe – deine eigentliche Arbeitsliste!)
  3. omnidesk_spezifikation_v2.pdf  (die fachliche Spezifikation)

STACK: Vite 8 + React 19 + TypeScript strict, Tailwind v4 (CSS-Config
in src/styles/globals.css, kein tailwind.config.js), Shadcn/ui,
React Router v7 (Lazy Loading ueber src/config/modules.ts),
TanStack Query, Clerk (Auth), Drizzle ORM + Neon Postgres,
Hono-API-Server unter server/ (Port 8787, Vite-Proxy /api).

SETUP NACH DEM KLONEN:
  1. npm install
  2. Datei .env.local im Projektroot anlegen:
       VITE_CLERK_PUBLISHABLE_KEY=pk_test_c2hhcnAtcmVkZmlzaC0yMi5jbGVyay5hY2NvdW50cy5kZXYk
       DATABASE_URL=<trage ich selbst ein – Neon-Dashboard>
  3. npm run db:push   (Schema nach Neon syncen)
  4. Zwei Terminals: npm run dev  UND  npm run dev:api

REGELN (unveraendert einhalten):
  - Farbthema strikt: Hintergrund #09090b, Kacheln #18181b, Text
    #fafafa, Sekundaertext #a1a1aa, Gradient #230d8f -> #cf0a0a.
    Fertige Utilities: bg-gradient-accent, text-gradient-accent,
    glow, glow-strong. Nur Shadcn-Komponenten verwenden.
  - Strikte Modultrennung: jedes Modul unter src/modules/<id>/ mit
    index.tsx als einzigem Export; neue Module NUR ueber die
    Registry src/config/modules.ts anmelden (Route+Sidebar+Toggle
    entstehen automatisch). Ein Drizzle-Schema pro Modul in
    src/db/schema/, immer mit user_id-Spalte + Index.
  - API: neue Hono-Route unter server/routes/, in server/index.ts
    mounten (oeffentliche Routen VOR der requireAuth-Middleware).
    Zod-Validierung; bei .partial()-Updates KEINE .default()s.
  - Jede Aenderung mit npm run build verifizieren und Module im
    Browser end-to-end testen (Dev-Server + eingeloggter User).
  - UI-Texte auf Deutsch. Toasts fuer Erfolg/Fehler.

DEINE NAECHSTEN AUFGABEN IN DIESER REIHENFOLGE:
  1. npm run build ausfuehren; Projektmanagement-Modul im Browser
     testen (Projekt anlegen, Board-Aufgaben verschieben,
     Meilensteine abhaken) und Fehler beheben
  2. Befehlsbibliothek E2E testen (Starter-Import, Suche, Copy)
  3. Passwort-Manager-Frontend: Client-seitige Krypto in
     src/lib/crypto.ts (Web Crypto API: PBKDF2, 310000 Iterationen,
     SHA-256 -> AES-256-GCM; Base64-Helfer). Ablauf: /api/vault/meta
     null -> Setup-Screen (Master-Passwort setzen, Salt+Verifier
     hochladen); sonst Unlock-Screen (Verifier entschluesseln =
     Passwort-Check). Schluessel NUR im Speicher (zustand), nie
     persistieren. Eintraege {title, username, password, url, notes}
     als JSON verschluesseln -> POST /api/vault/entries
     {category, ciphertext, iv}. Kategorien: privat/familie/kunden.
     UI: Liste mit Suche+Kategorie-Tabs, Copy-Buttons, Reveal,
     Lock-Button. Anzeige-Erwartung: Passwoerter maskiert.
  4. Booking-Frontend: (a) Konfigurations-UI im Kalender-Modul
     (Slug, aktiv, Slot-Minuten, Wochentags-Zeiten) gegen
     /api/booking/settings; (b) OEFFENTLICHE Seite /book/:slug –
     in src/app/App.tsx eine Route VOR dem SignedIn-Gate einbauen,
     Seite nutzt /api/public/booking/:slug (+ /slots?date=, /book),
     Ablauf: Tag waehlen -> freie Slots -> Name/E-Mail/Anliegen ->
     Buchung -> Bestaetigung. OmniDesk-Design, aber ohne Sidebar.
  5. PWA: vite-plugin-pwa (Manifest de, Theme #09090b, Icons im
     Gradient-Look generieren, registerType autoUpdate)
  6. Vercel-Deployment vorbereiten: api/-Ordner mit Hono-Vercel-
     Adapter (hono/vercel), vercel.json (SPA-Rewrites), README-
     Abschnitt Deployment. Achtung: Booking-Slotberechnung nutzt
     Serverzeit – auf Vercel (UTC) Zeitzone Europe/Berlin beachten!
  7. Danach Phase 4 laut Spezifikation (Gmail-Klon, Cloud-
     Monitoring Google Drive + MEGA via OAuth2) – dafuer frage
     mich nach Google-OAuth-Credentials.
