3. ARCHITEKTUR IM PRODUKTIVBETRIEB (WICHTIG FUER ALLE KUENFTIGEN
   SESSIONS – HIER NICHTS LEICHTFERTIG AENDERN!)
---------------------------------------------------------------------
  - Vercel baut mit DEM Befehl aus vercel.json:
      "buildCommand": "npm run build"
    und npm run build = tsc -b && vite build && bundle:api
    (bundle:api = esbuild bündelt api/[[...route]].ts inkl. server/
    und src/db zu einer eigenstaendigen api/index.js)
  - vercel.json enthaelt zusaetzlich einen Rewrite: alle /api/* ->
    api/index.js (Catch-All-Routing fuer Hono)
  - api/index.js exportiert BENANNTE Methoden (GET, POST, PUT,
    PATCH, DELETE) statt default – Vercel ignoriert sonst die
    Responses (Symptom: ewiger Timeout / 500)
  - Serverless-Faustregeln (nach 3 Absturz-Fixes etabliert):
      a) KEINE Top-Level-Checks, die bei fehlender Env-Var werfen
         (sonst stirbt die GESAMTE Function beim Kaltstart, auch
         /health). Loesung: faule Initialisierung – server/auth.ts
         (getClerkConfig()) und src/db/client.ts (getDb() + Proxy-
         Export db) lesen Env-Variablen erst zur Laufzeit.
      b) app.onError in server/app.ts gibt bei Fehlern mit Praefix
         "ENV_FEHLT:" die fehlende Variable im JSON-Body preis –
         sofortige Diagnose im Browser moeglich.
  - Zeitzone: Vercel erlaubt TZ nicht (reserviert, immer UTC).
    server/timezone.ts fixiert BOOKING_TIMEZONE = 'Europe/Berlin'
    fest im Code – Booking rechnet daher korrekt.

  BUG 4 (18.09., nachts): Vercel baute einmalig NUR "vite build"
    (ohne API-Bundle) -> alle /api-Routen 404. FIX: verbindliches
    "buildCommand" in vercel.json (Commit 5c1f909). Kann nicht
    mehr auftreten, da der Bundle-Schritt fest im Build haengt.

===============================================================
NACHTRAG 19.09. – API-404-Ursache Nr. 4 (Rewrite-Regel)
===============================================================

SYMPTOM: Frontend OK, aber alle /api/* -> 404, obwohl die
Build-Logs bewiesen: api/index.js wurde erfolgreich gebaut
(108.6kb).

URSACHE: In vercel.json fehlte die Rewrite-Regel
  { "source": "/api/(.*)", "destination": "/api/index.js" }
Ohne sie erreicht kein Aufruf die Function (nur exakt /api).
Die Regel war bei einer frueheren Bearbeitung der vercel.json
verloren gegangen.

FIX: Regel wiederhergestellt (Commit 814bee1). Das Deployment
lief automatisch per Git-Push – der Build-Command-Fix in den
Vercel-Projekteinstellungen ist damit ebenfalls bestaetigt.

LERNREGEL: vercel.json braucht IMMER alle 3 Bloecke gemeinsam:
1. buildCommand: npm run build
2. rewrite /api/(.*) -> /api/index.js
3. rewrite SPA-Fallback -> /index.html
Fehlt einer davon -> 404. Bei JEDER Aenderung an vercel.json
beide Rewrites pruefen!
