    (VAULT_CATEGORIES exportiert).
  - server/routes/vault.ts (gemountet):
      GET  /api/vault/meta       -> Vault-Row oder null
      POST /api/vault/meta       -> einmalig anlegen (409 wenn existiert)
      GET  /api/vault/entries
      POST /api/vault/entries    {category, ciphertext, iv}
      PUT  /api/vault/entries/:id
      DEL  /api/vault/entries/:id
    Alle Blobs sind Base64-validiert. Der Server sieht NIE Klartext.

ZU BAUEN (Frontend, src/modules/passwords/):
  1. src/lib/crypto.ts (neu, shared lib):
     - deriveKey(masterPassword, saltB64): PBKDF2, 310000 Iterationen,
       SHA-256 -> AES-GCM-Schluessel 256 Bit (crypto.subtle)
     - encryptJson(key, obj) -> {ciphertext: b64, iv: b64}
       (IV: 12 Bytes crypto.getRandomValues, pro Verschluesselung neu)
     - decryptJson(key, ciphertextB64, ivB64) -> obj (wirft bei
       falschem Schluessel -> genau so das Master-Passwort pruefen)
     - Base64-Helfer (ArrayBuffer <-> String)
  2. Vault-Store (zustand, NICHT persistiert!): {key: CryptoKey|null,
     unlock(), lock()}. Der Schluessel existiert nur im RAM;
     Seiten-Reload = gesperrt. Lock-Button im UI.
  3. Ablauf in index.tsx:
     - GET /meta == null  -> Setup-Screen: Master-Passwort 2x,
       Salt erzeugen (16 Bytes), Key ableiten, Verifier =
       encryptJson(key, {check:'omnidesk'}) als EIN Base64-JSON-Blob
       (oder ciphertext+iv als JSON zusammen in verifier speichern),
       POST /meta. WARNHINWEIS anzeigen: Master-Passwort ist NICHT
       wiederherstellbar!
     - GET /meta != null -> Unlock-Screen: Passwort -> Key ableiten
       -> Verifier entschluesseln; Erfolg = entsperrt, Fehler =
       "Falsches Master-Passwort".
     - Entsperrt: Eintraege laden, jeden mit decryptJson entschluesseln.
       Eintrag-Klartext: {title, username, password, url, notes}.
       UI: Kategorie-Tabs (Privat/Familie/Kunden) + Suche, Liste mit
       Copy-Buttons (Benutzername/Passwort), Passwort maskiert mit
       Reveal-Auge, Anlegen/Bearbeiten-Dialog mit Passwort-Generator
       (optional), Loeschen. Design wie die anderen Module.
  4. E2E: Setup -> Eintrag anlegen -> Reload -> Unlock mit falschem
     Passwort (muss scheitern) -> richtigem Passwort -> Eintrag
     lesbar -> in Neon-Konsole pruefen, dass nur Ciphertext liegt.
